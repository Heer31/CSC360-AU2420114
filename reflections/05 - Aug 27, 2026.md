## 01 — Understanding Maven Projects

- Maven is a **build automation and dependency management tool** used for Java projects.
- Maven helps manage external libraries without requiring them to be downloaded and configured manually.
- A Maven project commonly contains a `pom.xml` file, which stores project and dependency information.
- The `groupId`, `artifactId`, and `version` are used to identify and organise a Maven project.
- Maven provides a standard project structure, making Java projects easier to organise and maintain.

---

## 02 — POM, JAR Files and Repositories

- The `pom.xml` file contains information about the project, its dependencies, and its configuration.
- A JAR file is essentially a **ZIP-based archive** that can contain compiled Java classes, resources, and metadata.
- Maven repositories store and provide access to JAR files and POM files.
- The **local repository** stores dependencies on the developer's computer.
- A **remote repository** stores dependencies that can be downloaded when they are not available locally.
- Maven searches the local repository first and retrieves missing dependencies from a remote repository when required.

---

## 03 — Maven Dependencies and Commands

- Maven automatically manages project dependencies using the information provided in `pom.xml`.
- Maven also supports **transitive dependencies**, where a dependency can automatically bring in other libraries that it requires.
- Different Maven commands perform different stages of the build process:
  - `compile` → compiles the project source code
  - `test` → runs the project's tests
  - `package` → creates the packaged application, such as a JAR
  - `install` → places the built artifact into the local Maven repository
  - `deploy` → publishes the artifact to a remote repository
- I learned that **installing** an artifact locally and **deploying** it to a remote repository are different processes.

---

## 04 — CI/CD and Software Development Workflow

- CI/CD stands for **Continuous Integration and Continuous Delivery/Deployment**.
- CI/CD allows software changes to be automatically built and tested as developers update a project.
- A typical workflow can involve:
  - Making changes to the source code
  - Building the updated project
  - Running automated tests
  - Packaging the application
  - Deploying the updated version
- This process helps detect problems earlier and makes software delivery more consistent.
- I understood that automation is an important part of maintaining reliable software projects.

---

## 05 — Character Encoding and Unicode

- Character encoding determines how characters are represented and stored by a computer.
- **ASCII** supports a limited set of characters and is mainly designed around basic English characters.
- **Unicode** provides a much larger character set to support languages and symbols from around the world.
- **UTF-8** is a widely used Unicode encoding that can represent a large range of characters.
- Using the correct character encoding is important when working with Java source files and text containing different languages.
- I learned that incorrect encoding can cause characters to appear incorrectly or become corrupted.

## 06 — Thinking Beyond Functionality

- Software should not be evaluated only by whether the program works.
- A good software solution should also consider:
  - **Time** → how efficiently the program performs tasks
  - **Memory** → how much memory the program requires
  - **Security/Risk** → how safely the software handles data and potential threats
  - **Maintainability** → how easily the software can be understood, modified, and improved
- This encouraged me to think about software development from a more **professional and practical perspective**.
- A program that works correctly is only one part of good software development; its efficiency, security, and long-term maintainability also matter.
